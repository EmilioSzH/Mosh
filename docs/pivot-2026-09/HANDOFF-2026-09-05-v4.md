## 2. What the research established (reconciled and corrected)

### 2.1 Market pattern: analysis → editable starting state → manual refinement

Ozone 12 (stereo; reference/genre/macros; editable 21-module chain), Neutron 5 (per-track; genre/profile; reference targets via Audiolens), Nectar 4 (vocal chain, editable), sonible smart:/pure: (per-track; cross-channel groups; named perceptual space snappy/punchy/dynamic/dense), RoEx Tonn (multitrack 2–32 stems via cloud API; processed stems + settings JSON; sub-minute figure applies to mastering; commercial C++ SDK in preview), LANDR (stereo; ReHance cleanup), Logic Mastering Assistant (stereo; loudness-compensated bypass), Suno Studio (generated multitrack; conversational edits; stems as audio or MIDI; ~100M users / 2M paid / ~$300M ARR, Feb 2026). **Agreed:** none of the products surveyed accepts free-text direction on a full multitrack session while hearing it and leaving an editable, undoable result. **Not established:** that no such product exists, or any keep-rate denominator for automated first passes. Usable Mosh outcomes matter more than declaring the lane empty.

### 2.2 Research: architecture evidence, not dependencies

FxNorm-Automix (ISMIR 2022; 14 engineers avg 11.6 yrs; **code MIT**, R03). Diff-MST/-MSTC (reference → editable console params, up to 20 tracks; **CC-BY-NC-SA 4.0**). ST-ITO/ITO-Master (inference-time parameter search over arbitrary effect chains; **code Apache-2.0**, R02; dependencies/checkpoints separate). Text2FX/InstructFX2FX (open-vocabulary text → EQ/reverb params via CLAP; the 9/10 result is a feature-distribution metric, not listener wins; Text2FX code license **UNVERIFIED**). MixAssist (431 audio-grounded dialogue turns, 12 producers; advice, not execution). LLM2Fx-Tools (audio-aware tool calls; LLM-as-judge). Diff2Mix / two-stage mixing (2026; Apple-Silicon path **UNVERIFIED**).

**Rule-3 ruling:** an inference-time search that explores N settings and presents the best-scoring one is **proxy selection** — the score filtered N−1 candidates the owner never heard. **Not in this plan** without a written contract exception. Allowed: the model observes, makes **one** bounded proposal, the owner hears it. **The supplied research passes did not locate a study showing that audio descriptors fed as text improve an LLM's mixing decisions** — a search limitation, not a literature claim; §8 tests it in-house, blind, with/without.

### 2.3 Plugin introspection and the Live handoff

VST3 `ParameterInfo` (title, shortTitle, units, stepCount, default, flags), `getParamStringByValue`, normalized↔plain; controller must be connected to the component before counts are right. AU `AudioUnitParameterInfo`. JUCE `AudioProcessorParameter::getName/getLabel/getText/getValueForText/getNumSteps` via `AudioPluginInstance::getParameters()`. **Normalized values are not the defect; unidentified parameters and guessed meanings are.** Metadata is a discovery aid, not proof of acoustic meaning or complete restoration. **VST 3.8 SDK is MIT** (2025-10-29); check the *pinned* SDK/JUCE/Tracktion terms. `.als` VST3 blob ↔ `.vstpreset` compatibility **UNVERIFIED**; one empirical test; not on the critical path. pedalboard (GPL-3) and DawDreamer are lab tools; Mosh has a host.

**Live 12 export (manual §5.1.3; help center; R06):** "Export All Individual Tracks" = post-fader, aligned, same length; "Include Return and Main Effects" prints those treatments into each stem — **leave OFF for remixable parts**; **groups export with group treatment and children export without it — choose group *or* children by whether the group treatment is integral; summing both duplicates content**; frozen tracks render frozen; cross-track sidechains may break; 32-bit float recommended; **post-fader stems already contain level/pan — do not reapply imported mixer values**; disable automatic warp/pitch/fade on import. **A true null test is reserved for the same deterministic signal path**; the master-treated rough is not that path — a real song gets a listening acceptance. The rough with the owner's master chain is an **immutable reference**.

## 5. Label definition adopted for Rule 2

## 7. Operating boundaries — requirements for the plan, not a new architecture

**7.1 Trustworthy bounded control.** Actual IDs, fresh values, unit-aware conversions, explicit targets, a bounded allowlist (first: fader/pan/mute, vocal reverb send, a few builtin EQ/comp controls, automation ops that pass the audit). Do not load every plugin's parameter list into each turn. External effects: read names/labels/display text on demand for a few controls on one or two already-installed relevant effects; generic/ambiguous parameters read-only or manually mapped; version/instance changes invalidate mappings. Read back the actual processor value after every mutation. Distinguish serialized equality, effective parameter equality and audible equivalence; document nondeterministic plugins. **A long-running job binds to a session revision** and reconciles or cancels if state changed; one bounded edit = one undo transaction; undo never deletes original take audio. **Exactly-once has two halves:** a retry of the *same* operation is idempotent, and a *new* instruction that happens to repeat the words is a new operation — starting at −10 dB, "lower the vocal 3 dB" → −13; retrying that operation → still −13; "another 3 dB" → −16.

**7.2 Audio handoff without project reconstruction.** Mix Package v0 = a documented file set + the existing project manifest, not a new import subsystem: source filenames/hashes, common start, sample rate, active-source choice (group *or* children), printed processing, reference-only files, known missing controls. Version any new sidecar. Aligned PCM at session rate; 32-bit float where supported; normalize/loop off; Return/Main effects OFF for remixable parts; shared returns handled separately or the appropriate group printed; sidechains and nonlinear buses need a targeted fixture. A deterministic unprocessed fixture survives import/save/reopen unaltered; a real song gets the owner's listening acceptance. Never silently replace missing tracks, plugins or files.

**7.3 Recording takes precedence over agent availability.** Nothing (inference, network, disk serialization, analysis, speech recognition) on the audio callback; capture continues if the agent/provider stalls or dies. Raw captures preserved; monitoring effects non-destructive. "Turn me up" distinguishes headphone/cue level, final-mix level and hardware input gain — a fader cannot repair a clipped ADC. **Recovery contract:** separate completed takes, the current take's durably written frames, and the uncommitted tail; on abrupt process stop, completed takes survive, committed audio is recovered and attached to the right take, lost tail is **measured and disclosed** (proposed application-crash target ≤1 s on the selected setup; an unbounded or unexplained gap blocks the recovery claim). Device disconnection and power loss are separate classes. Never synthesize missing audio. **Voice is a separate integration:** start from the existing hold-to-talk path or a short explicitly enabled command window; test positive triggers (start/repeat/stop/cue) and negative ones (lyrics/playback that sound like commands); physical stop/control fallback always present; state which mode is actually hands-free.

**7.4 Direct refinement and honest observation.** First macro: "lead-vocal reverb amount" bound to a **verified** send; shows its target, keeps a reset point, survives reopen, undoes through MoshOps, moves without a model call; coupled targets only when explicit. Observation is a narrow read-only path: every reading names tap, track/bus, time range, window, session revision, freshness; silence/missing/failed are explicit states. **Do not manufacture precision:** missing quantities (integrated/short-term LUFS, oversampled true peak, per-track spectral energy, stereo correlation) need their actual PCM inputs and algorithms — usually via the existing offline-render path, after the gate — not renamed meter values. **Measurement fixture ≠ perception experiment:** recovering a known −6 dB change validates a measurement (code gate); an LLM diagnosing what sounds better is an experiment, never a gate on what the owner hears. Candidates are shown blind in random order independent of any score.

**7.5 Locality and rights.** Verified M1 Max workflow first; "PyTorch" is not proof of MPS performance or recording latency; any new backend needs a measured smoke test, peak memory, wall time, failure behavior, version/license record. No purchases, uploads, model-term acceptances or training in the planning pass.

## 9. Evaluation protocol (rule 3: ears only)

1. Same source performance; lossless renders; static playback-gain match (proposed within 0.2 LU); offset stored, never influencing the verdict.
2. Randomized, blinded labels; a few concealed repeats per milestone, counted 0 toward Rule 2.
3. Verdict = preference + one sentence; "no meaningful difference", "neither acceptable", "uncertain" are valid. Ask which track offends **where he can tell**; do not require it — the agent is supposed to help with that.
4. Two controls: the **preserved imported starting state** (effect of a Mosh change) and **his stereo-bounce shortcut** (end-to-end usefulness). Do not blame the agent for a failed import or credit it for a better export.
5. Concealed-repeat handling: report agreements/disagreements with denominators across sessions; a reversal may be a near tie, changed intent, fatigue or a protocol fault — check level/order/segment errors first; repeat **once** only when the unresolved comparison changes the decision. No automatic invalidation of a sitting; no repeat-until-pass.
6. Reserve ≥1 song unseen for step 7. Two milestone questions: *first-pass value* ("which would you rather start finishing from?") and *final value* ("after ≤20 min of direction, which would you keep?").
7. A silent technical failure, stale read or dropped vocal is a **failed operation**, not an aesthetic rejection. No unrecorded cherry-picking. DSP measures are inputs and diagnostics; they never order, filter or gate what the owner hears.

## 10. Day-90 decision matrix

| Evidence earned | Permitted next claim |
|---|---|
| Useful first passes and revisions, reliable capture, real voluntary reuse, **and** a preferred intervention that required component access | Private recording/mixing beta on the tested setup, multitrack included; no general professional-quality claim |

| First pass weak; corrected mix useful quickly | Directed mix assistant; autonomous first pass unearned |
| Mixing useful; recording still unsafe | Mixing-only scope; unsafe capture unavailable |
| Recording reliable and convenient; mixing unhelpful | Recording assistant + existing production tools; no mixing-intelligence claim |
| Preference inconsistent on near ties | Report uncertainty; controlled repeat once where decision-changing; do not discard the owner or optimize a proxy |
| No voluntary use, or neither job helps | Stop expansion, diagnose; a new platform still needs postmortem + cooling week + sign-off |
